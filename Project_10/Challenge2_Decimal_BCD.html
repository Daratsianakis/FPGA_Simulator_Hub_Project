1. Why convert binary to BCD?

Binary-coded decimal stores one decimal digit in each four-bit group. A value such as 253 becomes three BCD groups: 2, 5 and 3, rather than the two hexadecimal digits FD.

2. How the conversion works

The converter processes input bits from most significant to least significant. Before each shift it adds three to any BCD group that has reached five. This double-dabble process produces valid decimal digit groups.

3. Preserve the complete ALU

The same two registers, eight operations, three opcode switches, and four status outputs remain intact. The binary result feeds an additional BCD conversion path.

4. Result view

With SW7 off, the four-digit seven-segment display shows the eight-bit F value in decimal, padded to four places. Values range from 0000 to 0255.

5. Operand view requires selection

Two arbitrary eight-bit operands can each need three decimal digits, so they cannot both fit on four physical digits simultaneously. SW7 enables operand view, and the spare BTN2 chooses A or B. This is an explicit extension to handle the four-digit hardware limit.

6. Trace the display path

The active binary value travels through a BCD converter. Three decimal digit groups then feed the display controller. The selected source is highlighted in the architecture diagram.

7. Understand truncation

All calculations still produce the eight-bit F result. For example, 20 × 20 equals 400 mathematically, but F contains 144 after eight-bit truncation. The decimal display shows 0144 and overflow indicates discarded upper bits.

8. Practice

Try A=200, B=55 and ADD. The result view shows 0255. Switch to operand view, then press SELECT A/B to inspect the two three-digit decimal operands separately.

Operation codes: 000 ADD · 001 INC · 010 SUB · 011 MUL · 100 NOT · 101 XOR · 110 OR · 111 AND. Only the low eight bits are presented as F.

module operand_registers(
    input wire clk,
    input wire [7:0] sw,
    input wire load_A, load_B,
    output reg [7:0] A = 0,
    output reg [7:0] B = 0
);
    always @(posedge clk) begin
        if (load_A) A <= sw;
        if (load_B) B <= sw;
    end
endmodule
